# N200/N400 复值生产复跑方案（任务 C 阶段 1，待审批）

> 状态：草案，等待用户审批与前置确认项回填。
> 边界：本方案只覆盖**复值链路在生产体系上的复现验收**（验收 1/2）。
> **不包含**手性态选择（阶段 2：复值随机初态/相位扭曲初态/phi 插值需
> 物理决策 + `dmrg.cpp` 初态改动，单独拟定）。
> 依据：`docs/COMPLEX_RUN_PROTOCOL.md`、`docs/PROTOCOL_MEASURE_SC_LRO_V1.md`、
> 消费侧数据目录清单（DMRG-data-processing CLAUDE.md）、N=64 冒烟验收记录。

## 1. 归档口径汇总（复跑必须逐项一致）

| 项 | 归档口径 |
|---|---|
| 几何 | HoneycombXC，Ly=4；N=200→Lx=25，N=400→Lx=50 |
| 物理参数 | t=0.3, t2=0.01, J=0.1, J2=0.01（t_J_3）；NumHole 按 doping |
| doping（N200） | d1_10(20洞)、d1_20(10洞)、d1_100(2洞)、d2_25(8洞) |
| doping（N400） | d1_10(40洞)、d1_20(20洞)、d1_40(10洞)、d1_80(5洞)、d2_25(16洞) |
| D 调度 | 两档：低档（500→1500 区间）与高档（2000→5000 区间）各一套（精确 D 列表待确认，见前置项 2） |
| 源点 | N200：49/50；N400：97/98 |
| refbonds | N200：`49,50` `50,51` `50,54`；N400：`97,98` `98,99` `98,102` |
| 计算环境 | Intel 2022.2.0（compiler/MKL/MPI）+ GCC 12.1.0 + OpenMP，8 MPI × 7 线程，256G56c，exclusive（`submit_dmrg_zk.sh` 同源） |
| 测量 | `measure1`（源点扫描）；`measureSC_fix_ref_ext`（mpirun -n 8，逐 refbond） |

## 2. 关键设计决策

1. **编译口径 = 归档口径（Intel 2022.2.0 + OpenMP）**。N=64 冒烟只验证了
   GNU 12.1.0 串行口径（无 OpenMP）；生产 D=1500/5000 大体系在 GNU 串行下
   不可接受。复值在 Intel 口径下尚未验证 → 方案步骤 0 先用 Intel 口径把
   N=64 冒烟复跑一遍（复值构建 = 去掉 `-DRealCode=ON`，Intel 2022.2.0 的
   icpc 可用），通过后才进入生产步骤。
2. **从头复跑**：复值二进制读不了归档 real MPS（`Error reading file`，
   元素类型不匹配）→ 每个 (N, doping) 组合必须从 Néel 初态从头跑完整
   D 调度，不能复用归档 MPS 续跑。成本与归档同量级（复值运算约 2-4 倍）。
3. **试点先行**：先跑 N200 d1_100（NumHole=2，与冒烟 doping 语义一致）
   的**低档 D**端到端（dmrg→测量→验收），验收通过并经审批后，再铺开其余
   组合与高档 D。
4. **验收口径**（沿用已批准的工具与判据）：
   - scs：独立 manifest + 数值硬判据（atol=rtol=1e-8）。注意生产体系上
     新复值链 vs 归档 real 链也是两条独立收敛链——N=64 冒烟 scs 通过了；
     若生产超差，先用 `tools/diag_measure1_diff.py` 诊断、按事实再定论，
     **不擅自放宽阈值**；
   - measure1：generic 口径（完整性 + 虚部≈0 + E0 一致为硬判据，
     re-diff 仅报告）；
   - E0/site：新复值日志 vs 归档日志。
5. **数据落点**：集群新 run 目录（`run_<N>_<doping>_complex/`），归档 run
   目录与消费侧 `Data/Data_N{200,400}/` **一律不动**；复值测量结果回传后
   的消费侧落点见前置项 5。

## 3. 执行步骤

### 步骤 0：Intel 口径复值小验证（前置门槛）

- 用 Intel 2022.2.0 环境（同 `submit_dmrg_zk.sh`）构建复值二进制
  （无 `-DRealCode=ON`，含 OpenMP）；
- 复跑 N=64 冒烟（`scripts/smoke_n64_run.sh` 的构建/计算/测量/verify 链路，
  编译环境替换为 Intel 口径；脚本本身可能需小改，改动单独评审）；
- 通过标准：`ALL STEPS OK` + `SMOKE VERIFY ALL OK`；
- **未通过则停止，先修复再谈生产**。

### 步骤 1：试点组合（N200 d1_100，低档 D）

1. 新建 `run_N200_d1_100_complex/`，params.json 与归档 d1_100 逐字段一致
   （几何、物理参数、NumHole=2、Sweeps/CutOff/LanczErr/MaxLanczIter、
   noise 数组——见前置项 1）；
2. 复值 dmrg 跑低档 D 调度（见前置项 2），确认收敛（能量/截断误差/熵）；
3. 测量：`measure1`（源点 49/50）+ `measureSC_fix_ref_ext`（3 个 refbond）；
4. 数据回传本地，verify：scs（vs 归档 1500 档数据）、generic、E0（vs
   归档低档日志）；
5. 验收通过 → 提交步骤 1 结果记录 → 审批步骤 2。

### 步骤 2：铺开（其余组合 + 高档 D）

- N200：d1_10、d1_20、d2_25（低档 + 高档 D）；
- N400：d1_10、d1_20、d1_40、d1_80、d2_25（低档 + 高档 D）；
- 每组合流程同步骤 1（dmrg → 测量 → 回传 → verify）；
- 建议按 doping 从大到小（空穴少→多）或先 N200 后 N400 的顺序分批，
  每批完成后回报状态。

### 步骤 3：验收与归档

- 全部组合的 verify 报告存档（随冒烟验收记录一起）；
- 协议文档记录复值生产复跑的完成状态与数据落点；
- 任何口径调整（如 scs 超差处置）必须走与 N=64 v2 相同的评审流程。

## 4. 前置确认项（审批时请一并回答）

1. **归档 params.json**：各 doping 的完整参数（noise 数组、Sweeps、
   MaxLanczIter、CutOff、LanczErr、Threads）——集群归档 run 目录里的副本，
   请提供路径或内容；
2. **D 调度精确列表**：低档与高档各自的 D 值序列（消费侧记录为
   "低 D 500/1000/1500 + 高 D 2000→5000"，需精确逗号列表）与每段 Sweeps；
3. **归档 run 目录路径**（集群），用于取 params.json 与日志；
4. **资源预算**：从归档日志的 CPU time 估算每组合两档 D 的节点时长，
   确认队列可用性；
5. **消费侧落点**：复值数据回传后在 DMRG-data-processing 的目录命名
   （建议新根如 `Data_Complex/` 或 `Data_N200_complex/`，不混入归档
   `Data/Data_N{200,400}/`）；
6. **范围确认**：9 组合全部复跑，还是按需子集。

## 5. 风险与纪律

- 复值从头复跑 ≠ 归档数据的简单重算：两条独立收敛链的涨落型观测量
  （如 sz）会有 D 截断误差量级的差异，属预期（N=64 冒烟已实测）；
- 手性态不会在本方案中出现（实初态 + 实哈密顿量 → 态保持实，虚部≈0）——
  本方案产出的是"复值口径的实值态数据"与复现验收，**不产生 d+id 证据**；
- 归档数据目录、消费侧目录、协议 tag 一律不动；
- 每步提交作业前按纪律审批，不自动 sbatch。
